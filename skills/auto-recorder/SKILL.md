# Auto-Recorder 问答记录器

在每次回答结束后，把 "用户这次问了什么" 提炼成 ≤30 字的精简标题，并将 "你本次回答的完整内容" **原样保存**整理成 QA 记录，持久化到项目根目录的 `question-log.md`，让用户日后可以快速翻阅、检索、并直接复制使用。

## 目标与产出

- **产出文件**：项目根目录 `D:\项目\ai-agents-from-zero\question-log.md`
- **写入方式**：**追加**。若文件不存在则先创建（写入标题头），若已存在则在文末追加，不覆盖历史记录。
- **语言**：与当次对话一致（默认简体中文）。
- **格式**：必须是**标准的 markdown**，遵循下方模板。

## 前置动作

1. 若 `question-log.md` 不存在，先以 `# Q&A 学习记录` 为题创建它，再追加第一条记录。
2. 若已存在，直接读取文末，在其后追加新记录，并用分隔线分隔。

## 记录流程

### 第 1 步：抽取问题并提炼标题
- 回顾用户**本轮最后一次提问**，提炼其核心意图。
- 生成一个 **≤30 字** 的简洁标题，作为该条 QA 的主题句（即问题本身或对问题的概括）。

### 第 2 步：原样保存回答内容
- 完整保留本次回答的内容，**不进行任何大幅度的总结、删减、浓缩或改写**。
- 回答中包含的**核心逻辑、技术步骤、配置、代码块、公式、Markdown 列表/表格**等务必原样保留，确保日后翻阅时能够直接复用。

### 第 3 步：组织成 QA 写入
- 每条记录用 `---` 分隔，作为 Markdown 内容。
- 问题用 `Q：<≤30 字的问题标题>` 标识。
- 回答用 `A：` 开头，换行后输出**完整的、未压缩的**回答正文（支持多段落和代码块排版）。

## 输出模板（严格遵守）

```markdown
---
Q：<≤30 字的问题标题>
A：
<原样保存的回答内容，保留原始排版、段落、Markdown 格式、代码块，不做总结精简>
```

## 示例

**示例 1（原样保存纯文本回答）：**
```markdown
---
Q：langchain 是什么？
A：
LangChain 是一个开源框架，旨在简化使用大型语言模型（LLM）创建应用程序的过程。它提供了：
- **组件**：用于处理语言模型的抽象，以及一系列的组件实现。
- **现成的链**：用于解决特定任务的组件内置组合。
它支持 Python 和 JavaScript/TypeScript，核心在于将不同的组件“链”接在一起，以创建更复杂的用例，如聊天机器人、检索增强生成（RAG）、Agent 智能体等。
```

**示例 2（原样保存含完整代码的回答）：**
```markdown
---
Q：LangChain 的 invoke 接口怎么写？
A：
在 LangChain 中，`invoke` 是 Runnable 协议的核心方法，用于调用链或组件。

示例代码如下：
```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

# 1. 初始化模型和提示词
model = ChatOpenAI(model="gpt-4o-mini")
prompt = ChatPromptTemplate.from_template("讲一个关于 {topic} 的笑话")

# 2. 组合成链
chain = prompt | model

# 3. 使用 invoke 调用
response = chain.invoke({"topic": "小明"})
print(response.content)
```
- **参数**：接收一个字典（对应提示词中的变量）或对应的输入格式。
- **返回值**：返回一个 `BaseMessage` 或链中最后一个组件的输出。
```

## 注意事项
- **拒绝精简**：千万不要擅自对回答内容进行精简、删减或压缩，务必保留所有的技术细节和完整代码，以保证复用价值。
- 避免"总结：""同前："等废话前缀。
- 若本次会话没有实质提问（纯闲聊、命令、短答如"好的"），**不追加**记录，避免噪音。
- 若不到触发时机，仅在对话结束时执行一次，不重复追加。
```
